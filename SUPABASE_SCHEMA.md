# Supabase schema

Inferred from `index.html`: `syncToSupabase()`, `loadFromSupabase()`, book creation/import, student CSV import, and borrow/return transactions. This is a proposed schema matching the app payloads, not an export of an existing database.

## Setup SQL

Run this SQL against a new Supabase database. Mixed-case column names must stay quoted: the app sends complete JavaScript objects directly to Supabase and reads the same names back. IDs are text generated by the app or imported from CSV, rather than UUIDs.

```sql
begin;

create table public.books (
    id text primary key,
    title text not null,
    author text not null default '',
    isbn text not null default '',
    tags text[] not null default '{}'::text[],
    status text not null default 'available',
    "borrowedBy" text,
    "createdAt" timestamptz not null default now(),
    "updatedAt" timestamptz not null default now(),
    revisions jsonb not null default '[]'::jsonb,
    constraint books_status_check
        check (status in ('available', 'borrowed', 'archived')),
    constraint books_revisions_array_check
        check (jsonb_typeof(revisions) = 'array')
);

create table public.students (
    id text primary key,
    name text not null,
    class text not null default '',
    "createdAt" timestamptz not null default now(),
    "updatedAt" timestamptz not null default now()
);

create table public.transactions (
    id text primary key,
    "bookId" text not null references public.books(id),
    "studentId" text not null references public.students(id),
    type text not null,
    archived boolean not null default false,
    "archiveReason" text,
    "createdAt" timestamptz not null default now(),
    "updatedAt" timestamptz not null default now(),
    "createdBy" text not null default 'system',
    revisions jsonb not null default '[]'::jsonb,
    constraint transactions_type_check check (type in ('borrow', 'return')),
    constraint transactions_revisions_array_check
        check (jsonb_typeof(revisions) = 'array')
);

create index books_borrowed_by_idx on public.books ("borrowedBy");
create index transactions_book_id_idx on public.transactions ("bookId");
create index transactions_student_id_idx on public.transactions ("studentId");

alter table public.books enable row level security;
alter table public.students enable row level security;
alter table public.transactions enable row level security;

commit;
```

The status/type checks are proposed validation of the values used by the UI. Book CSV imports accept arbitrary status text without validation; clean invalid values before uploading to this schema.

## Tables and fields

### `books`

| Column | SQL type | App meaning |
| --- | --- | --- |
| `id` | `text` | Primary key; normally `bk_<milliseconds>_<random>`, or a CSV ID. |
| `title` | `text` | Required book title. |
| `author` | `text` | Optional author, stored as an empty string when omitted. |
| `isbn` | `text` | Optional ISBN; text preserves leading zeros. Not unique in the app. |
| `tags` | `text[]` | Tag strings without the leading `#`; CSV uses semicolon separators. |
| `status` | `text` | `available`, `borrowed`, or `archived`. |
| `borrowedBy` | `text`, nullable | Logical reference to the current borrower's `students.id`. |
| `createdAt` | `timestamptz` | ISO timestamp supplied by the app. |
| `updatedAt` | `timestamptz` | ISO timestamp supplied when the app changes the book. |
| `revisions` | `jsonb` | Array of revision objects. |

### `students`

| Column | SQL type | App meaning |
| --- | --- | --- |
| `id` | `text` | Primary key; admission/student ID from CSV, preserving leading zeros. |
| `name` | `text` | Required student name. |
| `class` | `text` | Optional class label, stored as an empty string when omitted. |
| `createdAt` | `timestamptz` | ISO timestamp supplied at import. |
| `updatedAt` | `timestamptz` | ISO timestamp supplied at import; one import path does not refresh it for existing students. |

### `transactions`

| Column | SQL type | App meaning |
| --- | --- | --- |
| `id` | `text` | Primary key; `tx_<milliseconds>_<random>`. |
| `bookId` | `text` | Foreign key to `books.id`. |
| `studentId` | `text` | Foreign key to `students.id`. |
| `type` | `text` | `borrow` or `return`; returns create separate transactions. |
| `archived` | `boolean` | Whether the transaction has been archived. |
| `archiveReason` | `text`, nullable | Reason supplied when archiving. |
| `createdAt` | `timestamptz` | ISO timestamp supplied at creation. |
| `updatedAt` | `timestamptz` | ISO timestamp supplied at creation or archive. |
| `createdBy` | `text` | Firebase user's email, or `system`; not a Supabase auth user ID. |
| `revisions` | `jsonb` | Array of revision objects. |

Revision objects have this shape:

```json
{
  "action": "create",
  "reason": "Book added",
  "user": "librarian@example.com",
  "timestamp": "2026-11-12T08:00:00.000Z"
}
```

Book revision actions in the code are `create`, `edit`, `archive`, `import`, `borrow`, `return`, and `auto_return`. Transaction revision actions are `create` and `archive`. These objects are app-written history, not a database-enforced audit trail.

## Relationships and sync behavior

- `transactions.bookId` → `books.id` and `transactions.studentId` → `students.id` are enforced by the SQL above. Default foreign key behavior prevents deleting referenced records.
- `books.borrowedBy` → `students.id` is intentionally a logical relationship only. The app uploads books **before** students, so an enforced foreign key would reject a borrowed book referencing a student not yet uploaded. To enforce it, first change sync to upload students before books, clean orphan borrower IDs, then add the foreign key.
- Push performs individual upserts on primary key `id`, in the order books → students → transactions. It is not atomic and can leave a partial upload after an error.
- Pull selects every column from each table and replaces the corresponding local arrays. The app does not specify row ordering or pagination; database result limits can truncate large collections, and the dashboard's recent list relies on array order.
- There are no remote delete calls. Clearing local data does not delete Supabase rows; a later pull can restore them.
- Timestamps and revisions are managed by the app. SQL timestamp defaults apply only when a field is omitted; no update triggers are proposed.
- Archive reasons, Supabase connection settings, and local UI state live in browser localStorage and are not synced. There is no app-backed users table, storage bucket, due-date field, or fine model in this schema.

## Access control required before sync

The SQL enables row level security without adding access policies. It therefore does **not** grant the current browser client permission to sync data. A count query may return no visible rows without proving write access.

The app uses Firebase Google sign-in, then independently creates a Supabase client with a URL and anon key. It does not pass a Firebase token to Supabase or establish a Supabase Auth session. The Firebase login alone therefore does not give these database requests an authenticated user identity.

Before using this with student records, implement a verified identity integration or an authenticated backend, and add policies for the intended librarians. The current operations require SELECT, INSERT, and UPDATE access; DELETE is not used. Granting those operations unconditionally to `anon` would allow anyone with the public project credentials to read and modify the shared data. Never put a service-role key in this browser app.
